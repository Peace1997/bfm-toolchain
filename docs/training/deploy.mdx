# 04 部署

把训练好的全身操作模型部署到真机，实现全自主作业。本页以 **LingBot-VLA v2** 为范例。

:::note 路径约定
原始文档中的绝对路径来自某台开发机，本页统一替换为 `/path/to/...`。实际使用时替换为你自己的路径。
:::

## 一、前期准备

### 克隆与编译

边侧机克隆 `lejulab_platform` 仓库，切换到对应分支。

<Stub>

- 原文档的 clone 地址指向内部 GitLab，公开站点需改为 [开源仓库](https://atomgit.com/OpenLET/Lejulab_ARM) 地址
- 确认本流程对应的分支名

</Stub>

```bash
cd /path/to/lejulab_platform   # 必须在仓库根目录执行

conda deactivate   # 退出 conda；若提示符仍有 (base)，说明没退干净

# 若之前在 conda 环境下配置过 cmake，必须清掉缓存再配
rm -rf build
mkdir -p build && cd build

export ROBOT_VERSION=17   # 编译不是刚需，启动仿真/控制器时必须有

cmake .. -DFORCE_PURE_CMAKE=ON
make -j$(nproc)
```

### 配置控制器切换路径

在 `configs/deploy/roban_wholebody_deploy.yaml` 中指定两个字段：

| 字段 | 值 |
| --- | --- |
| `switch_cli` | `controller_switch_cli` 编译后的可执行文件路径，默认 `lejulab_platform/devel/lib/leju-rl-controller/controller_switch_cli` |
| `switch_library_path` | CycloneDDS 的两套动态库路径（`cyclonedds-cxx-0.10.2/lib` 与 `cyclonedds-0.10.2/lib`） |

```yaml
heft:
  # ...
  switch_cli: "/path/to/lejulab_platform/devel/lib/leju-rl-controller/controller_switch_cli"
  switch_library_path: "/path/to/lejulab_platform/src/lejusdk/3rd_party/x86_64/cyclonedds-cxx-0.10.2/lib:/path/to/lejulab_platform/src/lejusdk/3rd_party/x86_64/cyclonedds-0.10.2/lib"
  # ...
```

### 安装 CycloneDDS

在 LeTools-Learning 的 conda 环境中安装：

```bash
conda activate letools   # 没有就先建：conda create -n letools python=3.12

export CYCLONEDDS_HOME=/path/to/lejulab_platform/src/lejusdk/3rd_party/x86_64/cyclonedds-0.10.2
export CMAKE_PREFIX_PATH="$CYCLONEDDS_HOME${CMAKE_PREFIX_PATH:+:$CMAKE_PREFIX_PATH}"

mkdir -p /tmp/cyclonedds-python-wheel
python -m pip wheel \
    --no-deps \
    --no-build-isolation \
    --no-binary cyclonedds \
    --wheel-dir /tmp/cyclonedds-python-wheel \
    cyclonedds==0.10.2

python -m pip install \
    --force-reinstall \
    --no-deps \
    /tmp/cyclonedds-python-wheel/cyclonedds-0.10.2-*.whl
```

验证：

```bash
python -m pip show cyclonedds
```

## 二、机器连接

### 有线通信

用网线连接边侧机和机器人下位机，SSH 进机器人，添加并运行桥接脚本：

```bash
bash setup_bridge.sh
```

<details>
<summary>setup_bridge.sh 完整内容</summary>

```bash
#!/bin/bash

BRIDGE=br0

# 物理网卡名称（替换成实际接口名）
IFACE1=上位机网口名称
IFACE2=边侧机网口名称

if ip link show "$BRIDGE" &>/dev/null; then
    echo "错误：桥接接口 $BRIDGE 已存在，请先删除或使用其它名称。"
    exit 1
fi

if ! ip link show "$IFACE1" &>/dev/null; then
    echo "错误：物理网卡 $IFACE1 不存在，退出脚本。"
    exit 1
fi

if ! ip link show "$IFACE2" &>/dev/null; then
    echo "错误：物理网卡 $IFACE2 不存在，退出脚本。"
    exit 1
fi

BRIDGE_IP=192.168.26.1/24

echo "=== 停用接口 ==="
sudo ip link set dev $IFACE1 down
sudo ip link set dev $IFACE2 down

echo "=== 清除接口IP地址 ==="
sudo ip addr flush dev $IFACE1
sudo ip addr flush dev $IFACE2

echo "=== 创建桥接接口 ==="
sudo ip link add name $BRIDGE type bridge

echo "=== 将物理接口加入桥接 ==="
sudo ip link set dev $IFACE1 master $BRIDGE
sudo ip link set dev $IFACE2 master $BRIDGE

echo "=== 启动物理接口和桥接接口 ==="
sudo ip link set dev $IFACE1 up
sudo ip link set dev $IFACE2 up
sudo ip link set dev $BRIDGE up

echo "=== 给桥接接口分配IP地址 ==="
sudo ip addr add $BRIDGE_IP dev $BRIDGE

ip addr show $BRIDGE
ip addr show $IFACE1
ip addr show $IFACE2

echo "临时关闭桥接流量经过 iptables 过滤"
sudo sysctl -w net.bridge.bridge-nf-call-iptables=0

echo "=== 桥接配置完成 ==="
```

</details>

然后在电脑的有线网络设置里：**有线 → 齿轮图标 → IPv4 → 手动**

| 项 | 值 |
| --- | --- |
| 地址 | `192.168.26.10` |
| 子网掩码 | `255.255.255.0` |
| 网关 | `192.168.26.1` |

点击应用，把有线网络断开再连接。正常的话，边侧机可以 ping 通下位机 `192.168.26.1` 和上位机 `192.168.26.12`。

### ROS 通信（获取相机图像）

在一个终端里：

```bash
export ROS_MASTER_URI=http://192.168.26.12:11311
export ROS_IP=192.168.26.10
```

正常情况下，边侧机上 `rostopic list` 可以看到上位机的 topic 列表，`rostopic echo /camera/color/image_raw/compressed` 可以看到相机图像数据。

:::note
这里默认上位机相机是打开的。正常装了数采服务开机会默认打开，没装的话需要自己 launch 相机服务。
:::

## 三、推理运行

### 启动 model server

修改 launcher 中对应模型区域的配置。以 LingBot-VLA v2 为例需要修改 5 处：

| 字段 | 说明 |
| --- | --- |
| `checkpoint` | 模型权重，写到 `hf_ckpt` 一级，目录需包含 `*.safetensors` |
| `training_config_path` | 训练启动时 dump 出的 yaml + 命令行参数快照，在训练产物根目录 `{output_dir}/lingbotvla_cli.yaml` |
| `qwen3vl_path` | VLM base model 路径；可留空，使用训练 YAML 中的 `model.tokenizer_path` |
| `robot_norm_path` | 数据集的 norm stats JSON |
| `robot_config_path` | 固定使用 `lingbot-vla-v2/robot_configs/roban_wholebody.yaml` |

```yaml
# ============================================================
# LingBot-VLA v2 - Roban wholebody 23D state / 32D action
# ============================================================
lingbotvla2_roban_wholebody:
  # ...
  args:
    checkpoint: /path/to/weights/lingbot-vla-2-weights/global_step_40000/hf_ckpt
    training_config_path: "/path/to/weights/lingbotvla_cli.yaml"
    qwen3vl_path: /path/to/base_models/Qwen3-VL-4B-Instruct
    robot_norm_path: /path/to/lingbot-vla-v2/assets/norm_stats/roban_wholebody.json
    robot_config_path: "/path/to/lingbot-vla-v2/configs/robot_configs/roban_wholebody.yaml"
  # ...
```

### 启动部署

必须在前面配置了 ROS 通信的那个终端里执行。开始前可以 `rostopic list` 确认相机话题存在。

```bash
python kuavo_deploy/eval.py configs/deploy/roban_wholebody_deploy.yaml
```
