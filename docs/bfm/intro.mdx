# BFM 是什么

**BFM**（Behavior Foundation Model，行为基础模型）是这套工具链的核心。

它和「一个训好的策略」不是一回事。策略只会做一件事；BFM 在大规模行为数据上预训练，学到的是一整个**行为空间**——下游要一个新技能时，不是从零学，而是从这个空间里把对应的行为调出来。

所以新技能的成本从「重新训练」降到了「少量后训练」，这是整条工具链得以成立的前提。

<Stub>

- 补充预训练数据的规模与构成
- 说明行为空间的条件化方式（任务向量 / 语言 / 目标状态？）
- 补充参数量、推理耗时等基本规格
- 明确模型的开放范围（内部 / 客户 / 公开）

</Stub>

## 和传统运动控制的区别

| | 传统方法（MPC / 手工步态） | BFM |
| --- | --- | --- |
| 新技能成本 | 重新建模、重新调参 | 准备演示数据，后训练 |
| 泛化能力 | 依赖模型精度，出域即失效 | 依赖数据覆盖，可增量补数据 |
| 可解释性 | 高，每项都能追到物理量 | 低，主要靠评测验证 |
| 实时性 | 可能受在线优化拖累 | 前向推理，耗时稳定 |
| 调试手段 | 看物理量 | 看数据与评测指标 |

不是替代关系。底层的伺服环和安全保护仍然是传统控制，BFM 替换的是上面那层「怎么动」的决策。

## 使用前请先明确

**BFM 不是通用机器人大脑。** 它不理解语言指令，也不做任务规划。它接收结构化的目标输入，输出关节级控制量。

**能力边界由数据决定。** 预训练数据没覆盖到的形态、负载、地形，都可能失效。上真机前务必确认 [能力与边界](/docs/bfm/capabilities)。

**换本体不是免费的。** 关节构型不同，观测和动作空间就不同。跨本体使用需要额外适配，见 [硬件接口](/docs/reference/hardware)。
